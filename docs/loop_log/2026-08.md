## 设定百科 / 全局搜索模块落地 DreamTale 网页版（2026-08-06，Core→Storage→Features→UI 四步演进 + 浏览器联调沉淀）

### 触发问题

用户希望在 DreamTale 网页版中新增「设定百科 / 全局搜索」，对标番茄小说网、起点中文网的世界观管理体验：所有设定（角色 / 地点 / 功法 / 势力 / 事件 / 物品 / 概念 / 其他）统一索引，支持全局加权搜索、标签分类、导出为 Markdown/JSON 设定集，并在写作工作站右栏新增「当前正文匹配到的设定」mini 面板，避免边写边切页查设定。

### 执行流程

1. **底座层（Core Models + Storage Interface）**：
   - 新增 `web/src/core/models.js` → `ENCYCLOPEDIA_TYPES` 枚举（8 类 + 每类 icon/color）与 `EncyclopediaEntry` ES6 class（含 `tags / aliases / related_entries / first_appear_ch` 等字段，带 `toJSON / fromJSON`）。
   - 在 `web/src/storage/interface.js` 扩展 CRUD：`listEncyclopediaEntries / getEncyclopediaEntry / saveEncyclopediaEntry / saveEncyclopediaEntries / deleteEncyclopediaEntry / searchEncyclopedia / exportEncyclopediaMarkdown / exportEncyclopediaJSON`。

2. **存储后端（IndexedDB v2 升级）**：
   - `web/src/storage/indexeddb-backend.js` 把 DB_VERSION 从 1 升到 2，在 `onupgradeneeded` 分支新增 `encyclopedia` object store（主键 `[projectId, id]`，索引 `by-type` / `by-created`）。
   - 实现 `searchEncyclopedia` 多字段加权评分：name=100 / aliases=70 / tags=50 / summary=30 / content=10 / first_appear_ch=5，累计后按分数倒序。

3. **前端模块（encyclopedia.js + writing-station.js）**：
   - 新建 `web/static/js/features/encyclopedia.js`，三栏式布局（左侧分类 + 标签云；中部列表/卡片双视图；右侧详情抽屉）。
   - 功能：Ctrl+K 聚焦搜索；左侧分类数量统计；标签云 Top 30 字号随出现频率递增；导出对话框支持「仅当前分类 / 仅选中标签 / 含详细内容」三复选；示例项目首次进入自动写入 10 条 demo 词条（沈砚 / 阿箩 / 问渊剑尊 / 青云宗 / 寒江 / 残剑问渊 / 问渊九式 / 青云剑诀 / 剑冢试剑 / 筑基）。
   - 在 `web/static/js/features/writing-station.js` 右栏新增「设定百科」面板：`Features.DTEncyclopediaPanel({ entries, content })` 扫描正文里出现的词条名，按匹配数量倒序展示；点击词条在 encyclopedia 视图中打开详情（通过 `localStorage.dt_open_ency_entry + hashchange` 跨视图通信）。

4. **路由 + 样式 + 浏览器联调**：
   - 顶栏导航新增「📖 设定百科」（`#/encyclopedia`），`app.js` 的 `_renderViewInternal` 会调 `DreamTaleFeatures.renderEncyclopedia`。
   - 新增 `static/css/_encyclopedia-compat.css`（约 630 行，复用 app.css 变量体系 `--bg-* / --text-* / --accent-*`，覆盖 `ency-page / ency-card / ency-drawer / ency-modal` 四大容器）。
   - 浏览器联调修复：
     - **BUG A：`Class constructor EncyclopediaEntry cannot be invoked without 'new'`** — `EncyclopediaEntry` 是 ES6 class，encyclopedia.js 里 `EntryCtor({...})` 直接调用会抛错，改为 `new EntryCtor({...})`（三处：newEntry / saveCurrentEntry / seedDemoEntries）。
     - **BUG B：列表项重复渲染 ×2** — `renderList()` 被 `reload()` 调用两次（applyFilters 触发一次 + reload 末尾再调用一次），最终是浏览器缓存了旧脚本导致的错觉，新开 tab 后计数恢复为 10 条。
     - **BUG C：抽屉没打开** — 因为 BUG A 的异常导致 `drawerEl.classList.add('open')` 后续步骤未执行；修复 BUG A 后抽屉正常滑出，表单字段自动聚焦到 name。

### 关键教训

1. **ES6 class 与普通函数构造器必须做「调用方式兼容」或统一用 `new`（content_quality / state_drift）**：
   `EncyclopediaEntry` 在 models.js 写成了 ES6 class（`toJSON / fromJSON` 方法挂在 prototype，更清晰），但 encyclopedia.js 里写了一个 fallback `function (o) { return o; }` 来兼容 models 未加载的情况，然后两边统一写 `EntryCtor({...})` 调用。ES6 class 不允许 `[[Call]]`，只允许 `[[Construct]]`，必须 `new`。**教训：同一套代码里混用 class + plain function 构造器时，要么两边都改成 function（prototype 手挂），要么两边统一 `new` 调用（对 plain function `new` 也是合法的）。推荐后者——统一 `new`，fallback 的普通 function 配合 `new` 时会返回传入的对象且不报错，兼容。**

2. **「侧边栏 mini 面板」跨视图通信的极简方案：localStorage + hashchange（content_quality / context_budget）**：
   写作工作站需要点击 mini 面板里的词条跳到 encyclopedia 视图。本来想引入一个全局 EventBus，但 `writing-station.js` 是 `renderWritingStation` 的 IIFE 闭包，与 `encyclopedia.js` 不共享模块作用域，挂到 `window` 又污染。**最终用 `localStorage.dt_open_ency_entry + location.hash = '#/encyclopedia' + new Date().getTime()` 方案**：点击 mini 面板先写 localStorage 的「目标词条 id」，再改 hash（带时间戳强制触发 hashchange，即使当前已是 `#/encyclopedia`），encyclopedia 渲染完成后读回该 id 并 `openEntry()` + 清空。**教训：跨两个功能 IIFE 模块的最小通信 = localStorage 存 payload + hashchange 做触发信号，0 新增依赖、对单页路由友好。**

3. **新增「首启 demo 种子」要写「防重复写入」守卫（content_quality / vault_sync）**：
   `seedDemoEntries()` 每一次渲染 `#/encyclopedia` 都会被调用，如果 demo 里有重复名（如青云宗 / 沈砚）会导致同一作品多条。**方案：先 `storage.listEncyclopediaEntries(pid)` 取当前条目数量，`count > 0` 时直接跳过**，并把通知改成「已为示例项目填充示例设定词条 ✓」，不产生重复。

4. **浏览器联调 = 强制刷新 + 新开 tab，别信缓存（git_hygiene / deployment）**：
   修复 `EntryCtor` 后点新词条仍报「line:352」同一条错误，是因为 `static/js/features/encyclopedia.js` 被浏览器 HTTP 缓存（304 或内存缓存），evaluate 脚本里看到的 `innerHTML` 也是旧渲染结果。**经验：验证静态 JS/CSS 改动，一律 `close tab → new tab → navigate` 三连，不要在同一个 tab 里反复点，以免花半小时 chase 伪 bug。**

### 可复用资产

1. **多字段加权搜索模板（`searchEncyclopedia`）**：
   任何需要"按字段相关性排序"的全文搜索都可以用这个模板：字段分档给权重 → 命中后按「精确匹配 ×3 / 前缀匹配 ×1.5 / 包含 ×1」放大 → 累加后按分倒序。比简单 `toLowerCase().includes(q)` 的结果更贴近用户直觉（搜名字肯定比在正文里偶然提到更相关）。

2. **三栏式「分类 + 列表 + 详情抽屉」功能模块骨架（encyclopedia.js 前 400 行）**：
   `container.innerHTML = SHELL_HTML` 先铺三栏骨架，然后 `reload() → applyFilters() → renderLeft() → renderList()` 串联，左侧分类用 `<div class="ency-type-item" data-type="xxx">` 统一事件委托（`leftEl.addEventListener('click', e => { const t = e.target.closest('[data-type]'); ... })`），可复用于任何"分类浏览 + 详情"的管理后台 UI。

3. **跨视图 mini 面板 API 范式（`DTEncyclopediaPanel`）**：
   在 features 模块里导出 `{ panelHTML, bindHandlers(container, onOpenEntry) }` 两段产物，父模块先插 HTML 再 `bindHandlers(容器, 打开词条的回调)`，把「渲染」和「事件绑定」解耦，写作工作站与 encyclopedia 视图两个父模块都能直接复用。**范式：功能模块暴露 `{ html, bind }`，父模块按需装配；比直接返回一个"整块 mount 函数"更灵活——父模块可以把 HTML 插在 sidebar 的任何位置，也可以延迟绑定。**
